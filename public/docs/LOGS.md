# 运行日志与导出

在顶部「管理与工具 → 运行日志」打开。也可从「本机服务器」或工作流里的「查看与导出日志」进入，修图 Agent 也有本张照片的日志入口。

日志从 1.31.0 开始记录，包括服务启停、官方客户端异常、工作流开始／完成／失败／中断、图片任务状态、请求与实际模型、硬件路线和云端回退。实际模型未返回时保持未知。已有工作流不会重新执行来补日志。

按级别、类别、时间、工作流编号或运行信息查找；界面显示最近 200 条，默认每 5 秒更新，后台页面暂停刷新。失败记录可跳转到关联工作流的具体步骤，是否重跑仍由原工作流的请求账本与确认规则决定。

点击「导出脱敏日志 ZIP」，再点击「下载日志包」。指定工作流时额外附带步骤状态与尝试次数摘要。Windows 使用浏览器下载或桌面保存；安卓使用系统保存窗口，手机独立完成，无需电脑服务器。前后端分离时仍使用同源 API。

导出内容：

- `diagnostics.json`：版本、Node 版本、平台、架构、筛选和条数；超过 1000 条时标明截断。
- `events.jsonl`、`events.txt`：当前筛选的最近 1000 条脱敏日志。
- `workflow-summary.json`：可选的工作流状态摘要，不含工作流原始输入输出。
- `SHA256.json`：各文件的大小和校验值；界面另显示整个 ZIP 的 SHA-256。

日志采用允许字段清单和固定错误分类，不保存账号、凭据、Cookie、照片、图片文件名、原始提示词、AI 原始返回或机器绝对路径。仅保留程序目录内的相对调用位置。自由格式启动日志、Android 原生调试日志和官方客户端原始输出不会自动附加。查找文字也不会进入导出包。发送诊断包前仍可自行解压查看。

数据在当前程序的私有 `data/logs/`，不上传 GitHub。日志最多 5 个文件，每个 2 MiB；写盘失败改用最近 500 条内存记录，不中断修图。导出缓存最多保留 5 包，每包不超过 8 MiB；生成新包时清理旧包和超过 48 小时的包。网页保存到其他位置的 ZIP 由你自行管理。重启不清除照片或工作流，也不会恢复已轮转的日志。

查看、刷新和导出日志不访问模型账号或消耗出图额度。导出只打包日志元数据；照片项目备份继续使用原有项目备份功能。
